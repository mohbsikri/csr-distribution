# /configure-theme — L3 Prompt

You are executing the Cognitive Specification Runtime theme configuration skill.

Your objective is to create or manage a CSS theme file for the active workspace's HTML document output. The theme is used by `/export-views` when generating HTML deliverables.

---

## EXTRACT — Colour extraction guidance

When given a reference document (Word, PowerPoint, PDF, or image), analyze it visually to identify the design system.

### What to look for

**Primary colour** — the dominant brand/heading colour. Often found:
- In slide titles or Word document headings
- In the logo
- In table header backgrounds
- In divider lines or accent bars

**Accent colour** — interactive/highlight colour. Often found:
- In hyperlinks
- In highlighted cells or labels
- In bullet accent colours
- In button elements

**Background** — most documents use white (`#FFFFFF`). Identify if non-standard.

**Surface** — secondary background (card, table alternate row). If not explicitly visible: derive as a 5% tint of the primary colour on white, or use `#F9FAFB` (CSR default).

**Border** — divider / table border colour. If not explicit: use `#E5E7EB` (CSR default).

**Text** — body text colour. Usually near-black. `#111827` (CSR default) if not identifiable.

### Font extraction

Read the document's font settings. In .docx files, the heading and body fonts are explicitly named in the document styles (Calibri, Aptos, etc.). In PowerPoint, check the slide master.

If you cannot determine the font with confidence: keep the CSR default (`system-ui` stack). Do not guess font names.

### Colour conversion

Convert any extracted CMYK, RGB, or HSL values to 6-digit hex. Example: `rgb(30, 58, 95)` → `#1E3A5F`.

### Minimum viable extraction

Even if the document yields only 1–2 colours, generate the theme.css with those values and defaults for the rest. A partial theme is better than no theme.

## theme.css output format

The generated theme.css must:

1. Start with a descriptive comment block (see template below)
2. Only override variables that differ from `${CLAUDE_PLUGIN_ROOT}/templates/html/themes/default.css`
3. Use the same `:root {}` structure
4. List only modified variables — do not copy unchanged defaults

**Template:**

```css
/* ============================================================
   CSR Custom Theme — "<workspace_id>"
   Source: <reference_filename>
   Extracted: <ISO date>
   Generated by: /configure-theme EXTRACT
   ============================================================ */

:root {
  /* Colours extracted from reference */
  --color-primary:     #XXXXXX;   /* <what it was found in> */
  --color-accent:      #XXXXXX;   /* <what it was found in> */

  /* Colours defaulted (not identifiable in reference) */
  /* --color-text-muted, --color-surface, --color-border: CSR defaults */

  /* Typography */
  --font-heading: 'ExtractedFont', system-ui, -apple-system, sans-serif;
  --font-body:    'ExtractedFont', system-ui, -apple-system, sans-serif;
}
```

Include an inline comment after each extracted value noting where it was found. This ensures the extraction is auditable and correctable.

## Preview and user confirmation

Before writing theme.css, ALWAYS display the extracted values in a readable table and ask for confirmation:

```text
THEME EXTRACTION PREVIEW
========================
Source: <filename>

Variable               Extracted value       Source in document
--color-primary        #1E3A5F              Slide title text colour
--color-accent         #2563EB              Hyperlink colour
--color-text           (default #111827)    Not identifiable
--font-heading         'Calibri'            Document heading style
--font-body            'Aptos'              Document body style

Unchanged from CSR default: all other variables

Write this theme to workspaces/<workspace_id>/theme.css? [Y/n]:
```

Do not write the file until the user confirms.

---

## COPY — guidance

When copying a theme from another workspace:
1. Read the source theme.css first comment block to confirm it is a CSR theme (not a foreign file).
2. Read the `:root {}` variables and display them as a preview before copying.
3. Ask for confirmation before copying.

---

## RESET — guidance

Before deleting theme.css, display what will be lost (the theme name from the comment block) and what the fallback will be (CSR default Professional Blue).

---

## STATUS — guidance

When reporting STATUS, also list the effective visual impact:
- If default: "Documents will use navy (#1E3A5F) primary, blue (#2563EB) accent."
- If custom: "Documents will use the colours from <source_document_name>."
- If custom-pending: "No custom theme set — default will be used until /configure-theme EXTRACT runs."
