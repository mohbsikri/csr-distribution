# /configure-theme — Execution Specification

---

## Phase 1 — Workspace Resolution

Standard W1–W5, R4a–R4e. Build `WORKSPACE_ROOT = workspaces/<workspace_id>/`.

---

## Phase 2 — Operation Dispatch

Parse the operation from the command arguments:

- `EXTRACT <file_path>` → Phase 3
- `COPY <source_workspace_id>` → Phase 4
- `RESET` → Phase 5
- `STATUS` → Phase 6
- `LOGO` → Phase 7
- Unrecognised or absent: emit `STATUS: BLOCKED — Unknown operation. Supported: EXTRACT, COPY, RESET, STATUS, LOGO.`

---

## Phase 3 — EXTRACT Operation

### Step 3.1 — File existence check

Verify the reference document exists and is readable.

Supported formats: `.docx`, `.pptx`, `.pdf`, `.png`, `.jpg`, `.jpeg`.

If absent: `STATUS: CONFIGURE-THEME BLOCKED — Reference file not found: <path>.`

If unsupported format: `STATUS: CONFIGURE-THEME BLOCKED — Unsupported format. Supported: .docx, .pptx, .pdf, .png, .jpg, .jpeg.`

### Step 3.2 — Document analysis

Read and visually analyze the reference document to extract:

**Colours (priority order):**
1. Dominant heading / title colour → maps to `--color-primary`
2. Accent / highlight / button colour → maps to `--color-accent`
3. Background colour (if non-white) → maps to `--color-bg`
4. Surface / secondary background → maps to `--color-surface`
5. Border / divider colour → maps to `--color-border`
6. Body text colour → maps to `--color-text`

If a colour cannot be extracted, retain the CSR default for that variable.

**Typography:**
1. Heading font name → maps to `--font-heading`
2. Body font name → maps to `--font-body`
3. Monospace font (if identifiable) → maps to `--font-mono`

Font values must be quoted and followed by the system-ui fallback stack:
```css
--font-heading: 'ExtractedFont', system-ui, -apple-system, sans-serif;
```

### Step 3.3 — Preview extracted values

Display the extracted values to the user BEFORE writing the file:

```text
THEME EXTRACTION — Reference: <filename>

Extracted values:
  --color-primary:    #XXXXXX   (from: <source — heading colour / brand colour>)
  --color-accent:     #XXXXXX   (from: <source>)
  --color-text:       #XXXXXX   (from: <source>)
  --color-bg:         #XXXXXX   (from: <source>)
  --color-surface:    #XXXXXX   (default — not identifiable)
  --color-border:     #XXXXXX   (default — not identifiable)
  --font-heading:     'FontName', system-ui ...
  --font-body:        'FontName', system-ui ...

Unchanged from default: --color-success, --color-warning, --color-danger,
  --font-mono, --text-*, --space-*, --page-width, --border-radius, --line-height

Write theme.css to workspaces/<workspace_id>/theme.css? [Y/n]:
```

If user declines: abort with `STATUS: CONFIGURE-THEME BLOCKED — User declined. No changes made.`

### Step 3.4 — Write theme.css

Write `workspaces/<workspace_id>/theme.css`:

```css
/* ============================================================
   CSR Custom Theme — "<workspace_id>"
   Source: <reference_filename> (extracted <ISO date>)
   Generated by: /configure-theme EXTRACT
   ============================================================ */

:root {
  /* Extracted from reference document */
  --color-primary:    #XXXXXX;
  --color-accent:     #XXXXXX;
  --color-text:       #XXXXXX;
  /* ... only variables that differ from default ... */

  /* Typography */
  --font-heading: 'FontName', system-ui, -apple-system, sans-serif;
  --font-body:    'FontName', system-ui, -apple-system, sans-serif;
}
```

Include only variables that differ from the CSR default. Do not duplicate unchanged default values.

### Step 3.5 — Update workspace_config.md

Update `workspaces/<workspace_id>/runtime/workspace_config.md`:

- Set `**theme:**` to `custom`
- Set `**theme_path:**` to `workspaces/<workspace_id>/theme.css`
- Set `**theme_source:**` to the reference document filename

If workspace_config.md does not exist: create it with all required fields.

If write fails: emit WARNING. Non-blocking.

### Step 3.6 — Completion report

```text
STATUS: CONFIGURE-THEME COMPLETE
Workspace: <workspace_id>
Theme source: <reference_filename>
Theme file: workspaces/<workspace_id>/theme.css
Variables extracted: N
Variables defaulted: N

This theme will be applied automatically when /export-views runs.
To revert: /configure-theme RESET
```

---

## Phase 4 — COPY Operation

### Step 4.1 — Source workspace lookup

Verify `<source_workspace_id>` exists in `runtime/workspaces.md`.

If not found: `STATUS: CONFIGURE-THEME BLOCKED — Source workspace '<id>' not found in registry.`

### Step 4.2 — Source theme existence check

Verify `workspaces/<source_workspace_id>/theme.css` exists.

If absent: `STATUS: CONFIGURE-THEME BLOCKED — Source workspace '<id>' has no custom theme.css. Use EXTRACT to create one.`

### Step 4.3 — Copy

Copy `workspaces/<source_workspace_id>/theme.css` to `workspaces/<workspace_id>/theme.css`.

If copy fails: `STATUS: CONFIGURE-THEME BLOCKED — Copy failed.`

### Step 4.4 — Update workspace_config.md

Set `**theme:**` to `<source_workspace_id>-copy` and `**theme_path:**` to `workspaces/<workspace_id>/theme.css`.

### Step 4.5 — Completion

```text
STATUS: CONFIGURE-THEME COPIED
Workspace: <workspace_id>
Theme copied from: <source_workspace_id>
Theme file: workspaces/<workspace_id>/theme.css
```

---

## Phase 5 — RESET Operation

### Step 5.1 — Check for existing theme

If `workspaces/<workspace_id>/theme.css` does not exist: emit `No custom theme found — workspace already uses the CSR default. Nothing to reset.` Stop.

### Step 5.2 — Confirm

Ask for confirmation:

```text
RESET THEME — workspace <workspace_id>
This will delete workspaces/<workspace_id>/theme.css and revert to the CSR default theme.
Confirm? [y/N]:
```

If user does not explicitly confirm: abort with no changes.

### Step 5.3 — Delete theme.css

Delete `workspaces/<workspace_id>/theme.css`.

### Step 5.4 — Update workspace_config.md

Set `**theme:**` to `default` and clear `**theme_path:**`.

### Step 5.5 — Completion

```text
STATUS: CONFIGURE-THEME RESET
Workspace: <workspace_id>
Custom theme removed. /export-views will use templates/html/themes/default.css.
```

---

## Phase 6 — STATUS Operation

Read `workspaces/<workspace_id>/runtime/workspace_config.md` (if exists) and check for `workspaces/<workspace_id>/theme.css`.

Report:

```text
THEME STATUS — workspace <workspace_id>
  theme:        <default | custom | <source>-copy | custom-pending>
  theme_file:   workspaces/<workspace_id>/theme.css (exists / not found)
  theme_source: <reference document name, if known>
  effective:    workspaces/<workspace_id>/theme.css | templates/html/themes/default.css

Available workspace themes (other workspaces):
  <workspace_id_a>: workspaces/<a>/theme.css (custom)
  <workspace_id_b>: workspaces/<b>/theme.css (custom)
  (none — no other workspaces have custom themes)
```

## Phase 7 — LOGO Operation `[A3, 2026-11-01]`

Writes the `logo_path` field of `workspaces/<workspace_id>/runtime/workspace_config.md`. Until this phase existed, that field was seeded by `/workspace-lifecycle` with the comment *"set with /configure-theme if needed"* and read by `/generate-views` for the cover page, but **no operation of this command could write it**. The instruction pointed at a capability that did not exist.

### Step 7.1 — Parse the argument

`LOGO <file_path>` registers a logo. `LOGO NONE` clears it.

If no argument: `STATUS: CONFIGURE-THEME BLOCKED — LOGO requires a file path or the literal NONE.`

### Step 7.2 — Clear path (`NONE`)

Set `**logo_path:**` to `(empty — set with /configure-theme LOGO if needed)`. Report and stop:

```text
STATUS: CONFIGURE-THEME LOGO CLEARED
Workspace: <workspace_id>
Cover pages will be generated without a logo.
```

### Step 7.3 — Validate the file

Both checks are refusals, not warnings. An unresolvable or non-image `logo_path` produces a broken image in **every** exported document, and it is the reader who discovers it, not the author.

1. The file must exist. If absent: `STATUS: CONFIGURE-THEME BLOCKED — Logo file not found: <path>.`
2. The extension must be one of `.png`, `.jpg`, `.jpeg`, `.webp`, `.svg`. Otherwise: `STATUS: CONFIGURE-THEME BLOCKED — Unsupported logo format: <ext>. Supported: .png, .jpg, .jpeg, .webp, .svg.`

### Step 7.4 — Write

Set `**logo_path:**` to the path **as given**, relative to the repository root. Do not copy the file into the workspace: a logo belongs to the organisation, not to one project, and copying it per workspace creates as many stale copies as there are projects.

### Step 7.5 — Completion

```text
STATUS: CONFIGURE-THEME LOGO SET
Workspace: <workspace_id>
logo_path: <path>
Cover pages generated by /generate-views will carry this logo.
```

### Why `LOGO` is explicit rather than inferred during `EXTRACT`

`EXTRACT` already analyses a reference document and could pick an image from it. It deliberately does not. Deciding which image in a document is the logo is a judgement, and a wrong guess puts someone else's mark on a deliverable sent outside the team. The cost of asking is one argument; the cost of guessing wrong is a document that has to be recalled.
