# /configure-theme — L1 Contract

## Purpose

Extract a CSS design theme from a reference document (Word, PowerPoint, PDF, or image) and apply it to the active workspace. The resulting `theme.css` overrides the CSR default theme for all HTML documents generated by `/export-views`.

Can also be used to apply an existing workspace theme (copy from another workspace) or reset to the CSR default.

---

## Operations

| Operation | Description |
|-----------|-------------|
| `EXTRACT <file_path>` | Analyze a reference document → generate workspace theme.css |
| `COPY <source_workspace_id>` | Copy theme from another workspace to the active workspace |
| `RESET` | Remove custom theme.css → revert to CSR default |
| `LOGO <file_path>` | Register a logo image for document cover pages → writes `logo_path` |
| `LOGO NONE` | Clear the registered logo |
| `STATUS` | Show current theme and logo for active workspace |

---

## Inputs

| Operation | Required inputs |
|-----------|----------------|
| EXTRACT | Reference document path (Word .docx, PowerPoint .pptx, PDF .pdf, or image .png/.jpg) |
| COPY | Source workspace ID (must exist in registry with a custom theme.css) |
| LOGO | Image path (`.png`, `.jpg`, `.jpeg`, `.webp`, `.svg`) relative to the repository root, or the literal `NONE` |
| RESET | None |
| STATUS | None |

---

## Outputs

| File | Operation | Description |
|------|-----------|-------------|
| `workspaces/<workspace_id>/theme.css` | EXTRACT, COPY | Workspace-specific CSS theme |
| `workspaces/<workspace_id>/runtime/workspace_config.md` | EXTRACT, COPY, RESET | Updated `theme` and `theme_path` fields |
| `workspaces/<workspace_id>/runtime/workspace_config.md` | LOGO | Updated `logo_path` field |

> **`logo_path` gained a writer on 2026-11-01 (A3).** The field was seeded by `/workspace-lifecycle` with the comment *"set with /configure-theme if needed"*, and read by `/generate-views` for the cover page — but no operation of this command could write it, in any version. The instruction pointed at a capability that did not exist. `LOGO` is deliberately explicit rather than inferred during `EXTRACT`: picking which image in a reference document is the logo is a judgement, and a wrong guess puts someone else's mark on a deliverable.

> **Validation.** `LOGO` verifies the file exists and carries an image extension before writing. A path that does not resolve is refused, not recorded — an unresolvable `logo_path` produces a broken image in every exported document and is noticed by the reader, not by the author.

---

## Workspace Resolution

Standard W1–W5, R4a–R4e. The active workspace is the target.

---

## Preconditions

| ID | Condition | Action on failure |
|----|-----------|-------------------|
| P1 | Active workspace resolves (W1–W5, R4a–R4e) | BLOCKED |
| P2 | (EXTRACT only) Reference document file exists and is readable | BLOCKED |
| P3 | (COPY only) Source workspace exists in registry | BLOCKED |
| P4 | (COPY only) Source workspace has `theme.css` at `workspaces/<source>/theme.css` | BLOCKED |

---

## Theme extraction rules

When analyzing a reference document (EXTRACT operation):

1. **Extract dominant colours** — identify primary colour, accent colour, and background colour. Convert to hex.
2. **Extract typography** — identify heading font and body font by name. If not identifiable: retain CSR defaults.
3. **Map to CSS variables** — map extracted values to the CSR token vocabulary (`--color-primary`, `--color-accent`, `--font-heading`, etc.).
4. **Generate theme.css** — write a complete CSS file overriding only the variables that differ from the default. Include a descriptive comment block identifying the source document.
5. **Preview** — display the resulting CSS variables to the user for validation before writing.

---

## Failure Handling

| Condition | Behaviour |
|-----------|-----------|
| Reference document unreadable | BLOCKED — stop |
| Cannot extract colours from document | WARNING — use CSR default palette; still write theme.css with extracted typography only |
| Source workspace theme absent (COPY) | BLOCKED — stop |
| workspace_config.md write fails | WARNING — theme.css still written; continue |

---

## Completion States

```text
STATUS: CONFIGURE-THEME COMPLETE    — theme.css written; workspace_config.md updated
STATUS: CONFIGURE-THEME RESET       — theme.css removed; workspace reverts to default
STATUS: CONFIGURE-THEME COPIED      — theme copied from <source_workspace_id>
STATUS: CONFIGURE-THEME BLOCKED     — precondition failed; no changes made
```
