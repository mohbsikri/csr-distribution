# /diff-specification

## Purpose

Compare two versions of a specification and produce a structured delta report showing what changed between them.

Primary use case: after an EVOLVE + re-BASELINE cycle, compare the new BASELINED specification against the previous SUPERSEDED version to understand what changed and why.

This command is read-only. It does not modify any specification artifact or lifecycle registry.

---

## Inputs

```text
/diff-specification <base> [--from <spec_id>] [--to <spec_id>]
```

* `<base>` — required; the specification base name (e.g., `ri-condi-colo-technical-documentation-v1`)
* `--from <spec_id>` — optional; the older version to compare from (default: most recent SUPERSEDED)
* `--to <spec_id>` — optional; the newer version to compare to (default: current BASELINED)

If only one version of `<base>` exists (no SUPERSEDED entry in the lifecycle registry), report `STATUS: DIFF BLOCKED — no prior version to compare against`.

---

## Outputs

Delta report written to:

```text
WORKSPACE_ROOT/output/diffs/<base>_diff_<from_spec_id>_vs_<to_spec_id>_<date>.md
```

The `output/diffs/` directory is created if absent.

---

## Comparison Model

The diff compares the two specification versions across the following dimensions, in order:

| Dimension | Method |
|-----------|--------|
| Header fields | Field-by-field comparison (Status, Baseline Date, Baselined By, Spec ID) |
| Sections | Heading-by-heading: section added / removed / modified (character count delta as proxy) |
| Business Rules | Rule-by-rule by ID (BR-NNN): added / removed / modified |
| Technical Rules | Rule-by-rule by ID (TR-NNN): added / removed / modified |
| Constraints | Item-by-item by ID (C-NNN): added / removed / modified |
| Terms | Term-by-term by name: added / removed |
| Data model | Table-by-table by name: table added / removed; field-level changes noted |

Body content below the first `---` separator is the comparison scope. Header metadata fields above `---` are compared separately.

---

## Workspace Resolution

Standard R4a–R4e workspace resolution applies.

---

## Execution Rules

1. Resolve workspace (W1–W5, R4a–R4e).
2. Read lifecycle registry to locate from/to spec paths.
3. Verify both spec paths exist and are readable.
4. Load both specifications.
5. Perform dimension-by-dimension comparison.
6. Assemble delta report.
7. Create `output/diffs/` if absent.
8. Write delta report.
9. Report completion.

---

## Failure Cases

Stop and report `STATUS: DIFF BLOCKED` when:

* Workspace resolution fails.
* `<base>` not found in lifecycle registry.
* Only one version exists (no SUPERSEDED entry for `<base>`).
* Either spec path does not exist on disk.
* `output/diffs/` cannot be created.
* Delta report write fails.

---

## Completion Reporting

```text
STATUS: DIFF COMPLETE
STATUS: DIFF BLOCKED
```

---

## Validation Rules

| Rule | Check | Class |
|------|-------|-------|
| DS1 | Delta report exists at declared output path and is readable | BLOCKING |
| DS2 | Both from/to spec IDs are present in the report header | BLOCKING |
| DS3 | Summary table is present with all 5 dimensions | BLOCKING |
| DS4 | No write operations targeted any path outside `WORKSPACE_ROOT/output/diffs/` | BLOCKING |
| DS5 | Neither source specification was modified during execution | BLOCKING |
| DS6 | Lifecycle registry was not modified during execution | BLOCKING |
